# Unity変更時の検証ガイド

変更に関係する節だけ確認する。全項目の実行やテストの新設を毎回求めるものではない。

## 環境を確認する

- Unityのバージョンは `ProjectSettings/ProjectVersion.txt`、依存関係は `Packages/manifest.json` と `Packages/packages-lock.json` で確認する。
- 既存のテスト・CI・Editorツールを優先する。コマンドやEditorパスは実環境で確認し、未確認の実行例を成功した手順として記録しない。
- 開いているEditorと同じプロジェクトを別プロセスで同時実行しない。終了や再起動が必要なら未保存の作業に配慮する。

## 変更と検証の対応

| 変更 | 必要に応じて行う検証 |
| --- | --- |
| 純粋なゲームロジック | コンパイル、関連する既存のEditModeテスト。再発防止に意味がある場合のみテストを追加 |
| MonoBehaviour・入力・UI・シーン遷移 | コンパイル、関連するPlayModeテストまたはEditorでの動作確認 |
| シーン・Prefab・アセット・シリアライズ | インポート後の参照、Missing Script、Inspectorの値、関連シーンの再生 |
| アセットの移動・改名 | 対応する .meta の移動、GUID保持、参照元の正常性 |
| asmdef・パッケージ・プラットフォーム依存処理 | 関連アセンブリのコンパイル、対象プラットフォームのビルドなど影響に応じた確認 |
| 性能改善 | 同条件で変更前後を計測。測定条件と結果を短く記録 |
| 文書だけ | 内容、参照パス、差分の確認 |

## Unity特有の見落とし

- シリアライズ変更：既存のシーン・Prefab・ScriptableObjectで値が保持されるか。
- ライフサイクル変更：有効化・無効化、破棄、シーン再読み込みで二重登録や参照切れが起きないか。
- 非同期処理：対象の破棄後に処理が続かないか。キャンセルや例外を適切に扱っているか。
- Editor専用処理：プレイヤービルドにEditor依存が入り込まないか。
- Enter Play Mode設定に依存する処理：Domain Reload無効をサポートする場合、静的状態やイベントが残らないか。
- プラットフォーム固有処理：Editor内の成功だけで対象端末の動作を保証していないか。

## 結果の残し方

- 「実行した確認・結果・未確認範囲」を区別する。既存のエラーと今回の変更で発生したエラーを区別する。
- バッチテストは終了コードだけでなくテスト結果も確認する。コンパイル成功を動作テスト成功と表現しない。
- ログは最初の原因となるエラーと必要な前後だけを読む。全文を会話や文書に転記しない。
- 実行環境がない場合は静的確認を行い、Editorで必要な確認を具体的に引き継ぐ。
