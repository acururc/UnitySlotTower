## 3. 操作割り当て（FR-002）

| 操作 | マウス | キーボード案 |
| --- | --- | --- |
| 召喚する味方を選ぶ | 操作バーのアイコンをクリック | 1〜5 |
| 配置マスを選ぶ | フィールドへドラッグ＆ドロップ | 矢印キーでカーソル移動、Enter で決定 |
| 向きを選ぶ | 配置後に上下左右へドラッグ（アークナイツ式） | 矢印キー、Enter で決定 / Esc で取り消し |
| 配置中の味方を選ぶ | クリック | Tab で順に選択 |
| 撤退 | 選択中の撤退アイコン | X |
| 強化 | 操作バーの強化アイコン（種類ごと） | Shift + 1〜5 |
| ベット＋レバー | レバー（またはベット/スタートボタン） | Space |
| リール停止（左・中・右） | 各ストップボタン | J / K / L |
| 一時停止 / 再開 | 一時停止ボタン | P または Esc（配置操作中でないとき） |

- ベットとレバーは1回の操作にまとめ、押した時点で固定掛け金を自動で投入する。所持コインが足りなければレバーは反応せず、コインのアイコンが点滅する（FR-040）。
- キー割り当ては1つの InputActionAsset にまとめ、後から変更しやすくする。キーコンフィグ画面は作らない。
- 配置操作の解釈（T208）: 選択（1〜5／アイコンを押す）→ マス選び → 向き選び → 確定で支払う。召喚できない味方は選べない。選択中の味方をもう一度選ぶと選択をやめる。マウスはアイコンを押してマスで離す（アイコンをクリックしてからマスをクリックしてもよい）。マウスでの向きは、マスを決めた直後からポインターの方向（上下左右、マスの中心から半マス以上）を向き、フィールドをクリックすると確定する。マスの中心付近をクリックするとマス選びに戻る（マウスだけでの取り消し。2026-10-30 ユーザー要望でドラッグ式から変更）。フィールド外（操作バーなど）のクリックは確定に使わない。Esc は向き選び→マス選び→選択なしの順に1段階戻す。矢印は押した瞬間に1マス（押し続けで繰り返さない）。新しい選択の向きは右から始め、カーソルは前回の位置を引き継ぐ。

## 4. 進行と画面遷移（FR-005, FR-010, FR-013〜016）

```text
Title（ロゴだけ文字可） → 難易度選択（設定1〜6の筐体プレート） → Game
Game: [W1 準備] → [W1 戦闘] → [W1 クリア: ライフボーナス加算・ストック化] → [W2 準備] … → [W5 最終ボス撃破]
                                                     ↘ ライフ0 → リザルト（ゲームオーバー）
最終ボス撃破 → リザルト（クリア） → リトライ（同じ難易度で Game をやり直す）/ Title
```

- シーンは `Title`（難易度選択を含む）と `Game` の2つ。リザルトは Game 内のオーバーレイ。リトライは Game の再読み込みで初期化する（AC-004）。
- 準備フェーズ（C-2）: 各ウェーブ開始時、敵が出る前に配置できる時間を設ける。制限時間はなく、開始ボタン（▶）で戦闘が始まる。準備中は召喚の待ち時間を無視する（C-3）。スロットも回せる。
- ウェーブ終了時: 配置中の味方を種類ごとに数えて無料ストックに加算し、全員をフィールドから外す。ライフを満タンに戻し、残りライフ×係数のコインを加算する。
- 無料ストックがある種類は、コインを使わずストックから配置する（ストックを先に消費）。
- ライフ: 敵が1体ゴールに着くたびに、その敵の「ライフ減少量」だけ減る（中ボスは複数、最終ボスは全ライフを想定）。

## 5. ルールの詳細（承認済み要求の実装解釈）

### 味方（FR-020〜028）
- ステータス: 最大HP、攻撃力、防御力、攻撃間隔、攻撃範囲（向き基準のマス相対座標の集合）、ブロック数、配置マス種別、召喚コスト、待ち時間。
- ダメージ式（アークナイツ準拠）: `max(攻撃力 − 防御力, 攻撃力 × 0.05)`。
- 攻撃対象: 範囲内でゴールに最も近い敵。弓だけが空中敵を対象にできる。剣士とタンクはブロック中の敵を優先する。
- ヒーラー: 範囲内で HP 割合が最も低い味方（満タンだけなら回復しない）。バッファー: 範囲内の味方の攻撃力に倍率をかける（重ねがけしない。最も高い倍率だけが効く）。
- 役割は `units.csv` の `role`（`melee` 近距離・`ranged` 遠距離〔空中も狙える〕・`heal`・`buff`）と `buff_rate`（強化の倍率、他は1）で持つ。回復量は（強化後の）攻撃力で、最大HPを超えない。バッファーは自分を強化せず、自分では攻撃しない。
- 対象の判定: 敵は中心が入っているマスで範囲に入る。ブロック中の敵は範囲に関係なく優先して狙う。同じ条件なら先に出た敵、回復は先に配置した味方。攻撃・回復の対象がないあいだは攻撃間隔を消費しない。
- 1ステップの順序: 出現 → 移動（ゴール到着でライフ減少） → 敵の攻撃 → HP0の味方の消滅（ブロックしていた敵は再び進む） → 味方の行動 → HP0の敵の消滅（ブロックの空きを戻し、ドロップを抽選）。ライフは0で止まり、ゲームオーバーになったら戦闘は進まない。
- 強化: 種類ごとに段階 1〜5。段階ごとの倍率（HP・攻撃・防御）と費用をテーブルで持つ。強化した瞬間、配置中の同種全個体のステータスを再計算する（最大HPが増えた分は現在HPにも加算）。
- 撤退: 個体を消し、`召喚コスト × 返還率` を切り捨てで返す。ストックから出した個体も、その種類の召喚コストを基準に返す（C-3）。
- 配置上限: フィールド上の味方の総数。ストックからの配置も上限に数える（C-3）。

### 敵（FR-030〜033）
- ステータス: HP、攻撃力、防御力、攻撃間隔、移動速度、射程、空中フラグ、ブロック消費数（ボスは2以上）、ライフ減少量、ドロップ確率、ドロップ量（最小〜最大）。
- 近距離雑魚: ブロックされると、ブロックした味方を攻撃する。遠距離雑魚: 移動しながら、射程内の味方（高台を含む）を攻撃する。ブロックされると停止する。空中雑魚: ブロックされず、空中経路を進み、射程内の味方を攻撃する。
- ブロックの位置: 地上の敵は、ブロックの空きが消費以上ある味方のマスの手前の境界（マス中心の 0.5 マス手前）で止まる。既にそのマスの中に居れば、その場で止まる（2026-10-30 ユーザー確認）。
- ドロップ: 味方に倒されたときだけ、ドロップ確率で当たれば量を最小〜最大（両端を含む一様）で決める。ゴールに着いた敵は落とさない。乱数は戦闘に注入する（シード固定で再現できる）。
- 中ボス・最終ボス: 高HP・高ブロック消費。固有の行動は1〜2個（範囲攻撃、雑魚の呼び出しなど）をデータで持つ（詳細は M3 で決める）。

### スロット（FR-040〜045）
- 構成: 3リール × 21コマ、3段表示。有効ラインは5本（上・中・下段と斜め2本）。固定掛け金は 3枚。
- 図柄: 7、BAR、ベル、スイカ、チェリー、リプレイ。
- 抽選: レバーオン時に内部抽選で「成立役（フラグ）」を1つ決める。確率は難易度（設定1〜6）と状態（通常・確変）ごとのテーブルで持つ（FR-045）。
- 役: ハズレ / リプレイ（再遊技: コインを消費せず次ゲーム）/ ベル / スイカ / 角チェリー / 中段チェリー（レア役）/ BIG / REG。BIG・REG は中段チェリー・スイカとの重複当選も表で定義できるようにする（`slot_probabilities.csv` の role 列で役を `+` でつなぐ。例 `big+center_cherry`。各行は排他のフラグで、残りの確率がハズレ）。
- リール制御: ストップボタンを押した位置から最大4コマ滑らせて、成立フラグの図柄を有効ライン上に引き込み、成立していない役の図柄は蹴飛ばす（実機準拠）。成立していない役は決して揃わない（AC-041）。リプレイ・ベルはどの押し順・押し位置でも必ず揃う。スイカ・角チェリー・中段チェリーは押す位置が合わないと取りこぼし、ハズレの出目になる（2026-10-29 ユーザー決定。21コマ・4コマ滑り・押し順自由では常に揃う配列が存在しないため）。
- 払い出し: 役ごとに1ゲーム1回（複数ラインで揃っても加算しない）。チェリーは左リールにチェリーが止まれば成立し、中段なら中段チェリー、上段・下段なら角チェリー。
- 目押し要素: ボーナス図柄（7・BAR）はリール配列上の間隔の関係で、押す位置が合わないと揃わない。BIG・REG のフラグは揃えるまで次ゲーム以降に持ち越す（持ち越し中・重複当選時はボーナスを揃える期待値を最優先し、同じなら小役で比べて引き込む）。持ち越し中に引いたボーナス役は成立させず、重複当選なら小役だけが成立する（例 big+watermelon → watermelon、big → ハズレ）。
- ボーナス: BIG（7・7・7）と REG（7・7・BAR）。ボーナス中は専用の抽選表で毎ゲーム高確率で小役が揃い、払い出しの合計が上限（BIG 例 240枚、REG 例 96枚）に達したら終了する（FR-042）。累計はボーナス中に始めたゲームの払い出しだけを数え（ボーナス役を揃えたゲームは含めない）、上限をまたいだゲームの払い出しは削らずに全額払ってそのゲームで終える。ボーナス中も目押しは必要（押せば揃う程度の配列にする）。
- 確変: BIG 終了後、テーブルの突入率（初期値 100%）で確変に入る。確変中は N ゲーム（初期値 100G）のあいだボーナス確率が上がる。確変中に BIG を引くと N をリセットする（FR-043）。ゲーム数は確変中に始めたゲームで数え、ボーナスを揃えたゲームも1ゲームとし、ボーナス中は数えない。確変中の BIG は終了後に突入率で抽選し直し、当たれば N から数え直す。確変中の REG は終了後に残りゲーム数で確変に戻る（2026-10-29 ユーザー決定）。
- 先バレ: レバーオン時、成立フラグごとの発生率で、筐体ランプの点灯と専用音を鳴らす（FR-044）。ハズレでも低確率で発生させる「ガセ」をテーブルで持てるようにする（初期値 0%）。対象は 7揃いの BIG・REG だけ（2026-10-29 ユーザー決定。レア役とガセは 0）。表は単独の役と `hazure`（ガセ）の行で持ち、表にない役は発生しない。重複当選はその役のうち最も高い発生率で1回だけ抽選する。抽選は持ち越し中にボーナス役を外したあとのフラグで行い、ボーナス中も表どおり抽選する。
- 1ゲームの最短時間（ウェイト）: 初期値 2.0 秒。戦闘が止まらないので、実機（約4.1秒）より短くする。前のレバーオンから数え、待ち中に押したレバーは受け付けておき時間が来たら回す（実機準拠）。回転中のレバーは無視する。
- 筐体の仮表示（T110）: 先バレランプは先バレが起きたら点き、そのボーナスを揃えるまで消えない。ほかにボーナス中・確変中・リプレイのランプ。数字はクレジット、直前の払い出し、ボーナス中の払い出し累計（確変中は残りゲーム数）。先バレ音は素材を選ぶまで（T501）仮のチャイム。
- 機械割の目標（初期値）: 設定1 100% / 2 104% / 3 108% / 4 112% / 5 118% / 6 125%。設定1が最も難しい。テーブルから理論値を計算する Editor ツールを用意し、シミュレーションテストで実測と比べる（AC-040）。目標は適当打ち（押し順6通りと各リールの押し位置21コマを一様ランダム）での値に合わせる（2026-10-30 ユーザー決定）。理論値は「1ゲームの出目の分布（フラグ×持ち越しごとに全押し方を数え上げ）」と「確変残りゲーム数×持ち越しの状態遷移（ボーナスは上限までの払い出しを1回の遷移にまとめる）」の定常分布から出し、機械割は 払い出し合計 /（掛け金 ×（ゲーム数 − リプレイが揃った数））。ツールは参考に完全攻略（毎ゲーム、ボーナス→払い出しの順に最大になる押し方）の値も出す。

## 6. データテーブル（FR-050, D-32, C-1）

数値の正本は CSV。配置は `Assets/UnitySlotTower/Data/Tables/`。Excel などで編集し、保存形式は「CSV UTF-8（コンマ区切り）」とする。列名は英数字（例: `id,max_hp,atk`）で、1行目を見出しにする。

| ファイル | 主な内容 |
| --- | --- |
| `game_config.csv` | キーと値: 初期コイン、掛け金、ライフ、ライフボーナス係数、配置上限、撤退返還率 |
| `units.csv` | 味方5種のステータス、配置マス種別、ブロック数、コスト、待ち時間、役割と強化倍率 |
| `unit_ranges.csv` | 味方ごとの攻撃範囲（右向き基準のマス相対座標。向きに応じて回転） |
| `unit_upgrades.csv` | 種類×段階ごとの倍率（HP・攻撃・防御）と費用 |
| `enemies.csv` | 敵5種のステータス、空中フラグ、ブロック消費、ライフ減少量、ドロップ確率と量 |
| `maps/w1.csv` 〜 `w5.csv` | グリッドそのものを表で描く（1セル＝1マス。`G`地上 `H`高台 `X`通行不可 `S1`出現口 `E`ゴール など） |
| `map_paths.csv` | マップ・経路IDごとのマスの並び（地上経路と空中経路） |
| `waves.csv` | ウェーブ番号、出現時刻、敵の種類、出現口、経路、ボスかどうか |
| `slot_reels.csv` | 3リール×21コマの図柄配列 |
| `slot_payouts.csv` | 役ごとの払い出し枚数と揃う図柄 |
| `slot_probabilities.csv` | 役ごと × 設定1〜6 × 状態（通常・確変・ボーナス中）の成立確率（分母表記、例 `1/7.3`） |
| `slot_rules.csv` | キーと値: ボーナス上限枚数、確変ゲーム数と突入率、ウェイト、最大滑りコマ数 |
| `slot_premonition.csv` | 成立役ごとの先バレ発生率 |

- 読み込み: CSV は TextAsset として参照し、コア層のパーサーで読み取り専用データに変換する。プレハブ・アイコン・音などの「数値でない参照」は、CSV の `id` をキーにした ScriptableObject（`PresentationCatalog`）にまとめる。
- 検証: 全CSVを読み込み、型・範囲・ID参照・確率の合計（1を超えない）・マップの経路の連続性を確かめる EditMode テストを置く。CSV を壊すとテストが失敗し、エラーにファイル名・行・列を出す。
- 試し方: Editor のメニューから、実行中に CSV を再読み込みできるようにする（次のウェーブ・次のゲームから反映）。
- 機械割の計算: `slot_*.csv` から設定ごとの理論機械割を出す Editor ツールを作る（AC-040 の比較基準）。

## 7. マップとウェーブ（FR-010）

- グリッドは 9列×6行を基本にする（上部38%の横長領域に収まる大きさ）。マップごとに出現口・経路・高台の位置を変える。
- W1: 出現口1・一本道、近距離雑魚中心 → 中ボス。W2: 遠距離雑魚が加わる。W3: 空中雑魚が初登場（弓の必要性を体験させる）。W4: 出現口2つの分岐。W5: 全種混成 → 最終ボス。
- 1ウェーブの長さは 2〜3分を目安にする（全体 12〜15分）。具体的な敵の数とタイミングは M3 でプレイしながら決める。

## 8. 文字を使わない UI（FR-003, FR-004）

- フォントは数字（0-9）と記号（+ − × / %）だけを含む TextMeshPro フォントアセットを使う。それ以外の文字はそもそも表示できない作りにする。
- 自動チェック: Title 以外のシーンとプレハブの全テキスト部品を走査し、数字・記号以外の文字があれば失敗する EditMode テストを用意する（AC-001 を補う）。
- 説明の見せ方: 各要素を初めて使う場面（例: W1 開始時の召喚、初めてのボーナス）で画面を薄暗くし、対象を光らせて矢印と手のアイコンのアニメで操作を示す。一時停止中は「?」アイコンから、役の図柄＝配当数の早見表と、味方の能力（範囲図・数値）を見られる。
- 状態は色と形で区別する: 召喚可能（明るい）、コスト不足（暗い＋コインアイコン赤）、待ち時間中（円形ゲージ）、ストックあり（数字バッジ）。
